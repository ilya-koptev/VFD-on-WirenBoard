# Загрузка шрифтов в модуль без пересборки прошивки

Сейчас шрифты вкомпилированы в прошивку: чтобы добавить или поменять один, надо
пересобрать и перепрошить всё. Решение — отдельная область флеша под шрифты и
заливка их по шине как данных.

## Разметка флеша

Стенд NUCLEO-F411RE (512 КБ, секторы 16/16/16/16/64/128/128/128 КБ):

| Область | Адрес | Размер | Чем стирается |
|---|---|---|---|
| загрузчик | `0x08000000` | 16 КБ | сектор 0 |
| приложение | `0x08004000` | 48 КБ | секторы 1–3 |
| шрифты | `0x08010000` | 64 КБ | сектор 4 |

Целевой GD32E230 (64 КБ, страницы по 1 КБ):

| Область | Адрес | Размер |
|---|---|---|
| загрузчик | `0x08000000` | 8 КБ |
| приложение | `0x08002000` | 32 КБ |
| шрифты | `0x0800A000` | 24 КБ |

Страница 1 КБ у GD32 удобнее: шрифт можно заменить, не стирая соседние. На
стенде сектор один и большой, поэтому там при замене одного шрифта переписывается
вся область — для стенда это неважно.

## Каталог и формат

В начале области — каталог на четыре слота, по 32 байта на запись:

```
offset  4  адрес блоба относительно начала области (0xFFFFFFFF = слот пуст)
size    4  длина блоба, байт
crc32   4  контрольная сумма блоба
name   16  имя, ASCII, добито нулями
alloc   4  сколько места отведено слоту (для замены без сдвига остальных)
```

Блоб шрифта, читается прямо из флеша, без копирования в ОЗУ:

```
magic   4  'VFDF'
ver     1  = 1
kind    1  0 = только цифры и знаки, 1 = полный набор с картой символов
w,h     2  клетка, точек
by      1  байт на строку растра (= (w + 7) / 8)
glyphs  2  число глифов
ranges  1  число диапазонов кодов (для kind = 1)
resv    4  нули
далее:     ranges * {first:2, last:2} — карта кодов в порядке глифов
далее:     glyphs * h * by байт растров
```

Такой формат совпадает по смыслу с тем, что генераторы уже делают в виде
заголовков на C, поэтому `digitsgen3.py` и `gen_ttf_sets.py` переучиваются на
бинарный вывод, а не переписываются.

Рендер получает дескриптор `{ источник: вкомпилирован | флеш, указатель }`.
Нумерация шрифтов продолжается: 0–2 текстовые вкомпилированные, 3–10 наборы
цифр, 11–14 слоты из флеша.

## Заливка по шине

Регистры в регкарте, рядом с окном картинки:

```
FONT_CTL     slot      номер слота 0..3
             action    1 = стереть слот, 2 = начать приём, 3 = завершить и сверить
             size      длина блоба, байт (старшее слово вперёд)
             crc32     ожидаемая сумма
             status    0 = готов, 1 = приём, 2 = ошибка суммы, 3 = не влезает
FONT_WINDOW  offset    смещение порции в блобе, байт
             data[64]  128 байт данных
```

Порядок: `action = 1`, затем порции по 128 байт с указанием смещения, затем
`action = 3`. Модуль сверяет CRC32 и обновляет каталог одной записью — до этого
момента слот считается пустым, поэтому обрыв связи посреди заливки не оставляет
полуживого шрифта.

24 КБ на 115200 порциями по 128 байт — около 25 секунд.

Во время приёма поле гасится: запись во флеш останавливает выборку команд на
десятки микросекунд, кадр начинает дрожать, и мигание заметнее, чем пауза.

## Про механизм «прошивок компонентов» Wiren Board

У штатного флешера есть путь для обновления компонентов со своими подписями и
версиями — в исходнике `wb-mcu-fw-flasher` это регистры `0xFD00` (описание
компонента со шагом на каждый) и `0xFE80` (флаги наличия). Шрифт как «компонент»
ложится в эту идиому идеально, и тогда заливка шла бы той же командой, что
прошивка, без своих утилит.

Но семантика этих регистров по исходнику флешера восстанавливается не полностью:
видно адреса и то, что для компонентов режим загрузчика не нужен, а точный формат
описания компонента — нет. Поэтому порядок такой:

1. сначала свои регистры `FONT_CTL` и `FONT_WINDOW` — они простые и работают
   сразу, с обычным Modbus и любым скриптом;
2. потом, когда семантику компонентов удастся уточнить (по документации ВБ или
   вопросом им), добавить совместимый путь, не ломая первый.

## Порядок работы

1. Генераторы учатся писать `.vfdfont` вместо заголовков на C.
2. В приложении: чтение шрифта из флеша, дескрипторы источников, слоты 11–14.
3. Запись во флеш: стирание области, приём порций, сверка CRC32, каталог.
4. Регистры `FONT_CTL` и `FONT_WINDOW` в регкарте и в шаблоне.
5. Хостовая утилита `vfdfont_upload.py` по образцу `wbfw_flash.py`.
6. Выкинуть из прошивки лишние вкомпилированные наборы — освободится 4–5 КБ,
   и именно они станут первыми загружаемыми.
