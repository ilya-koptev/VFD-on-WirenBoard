# MN12832L (Noritake Itron VFD 128×32) — bring-up на NUCLEO-F411RE

Оживление графического вакуумно-люминесцентного дисплея **MN12832L** (chip-in-glass,
128×32 точки, куплен на AliExpress) с прицелом перенести драйв на **GD32E230** и
подключить дисплей к контроллеру **Wiren Board** через Modbus/RS-485.

Даташит: Noritake Itron, Doc.Ref 3772 Iss.1 (скан лежит вне репозитория).

## Стенд и распиновка

Плата запуска — NUCLEO-F411RE (STM32F411RET6). Логика 3,3 В подаётся **напрямую**,
согласователь уровней не нужен. Питание модуля — одна шина 5 В, накал и высокое
(≈47 В) плата поднимает сама.

| Сигнал модуля | Пин Nucleo | Arduino | Назначение |
|---|---|---|---|
| CLK | PA5 | D13 | такт сдвига (в рабочем режиме — битбенг, см. гочи) |
| SIN | PA7 | D11 | данные |
| LAT | PB6 | D10 | защёлка |
| BLK | PB4 | D5 | гашение (HIGH гасит) |
| EF | PB8 | D15 | включение накала, активен HIGH |
| HV | PB9 | D14 | не драйвим (Hi-Z), ни на что не влияет |
| SO1 | PA10 | D2 | обратка сдвигового регистра (для измерений) |
| GCP | PC7 | D9 | счётный клок ШИМ-декодера (на модуле посажен на землю, вывод задел на будущее) |
| GND | GND | — | общая земля |

Консоль: USART2 (PA2/PA3) → ST-Link VCP, **115200**.

## Что работает

- Кадровый буфер 128×32, рендер по даташиту: регистр 240 бит, строки 1…32 =
  биты 1…192 в порядке `afbecd`, сетки G1–G44 = биты 193…236.
- Последовательность из `MULTIPLEX TIMING`: сдвиг → пауза CLK → **LATCH** →
  импульс **BLK** → пачка GCP; сетки парами с перекрытием, 44 слота.
- Тайминги в норме даташита: CLK ≥ 400 нс, LAT high ≥ 300 нс, BLK hold ≥ 10 мкс,
  период слота выровнен по таймеру (`cfg slotus 220`) ⇒ кадр 9,7 мс, 103 Гц.
- `clr` даёт идеальный чёрный (max 0), `fill` — ровное поле по всей площади,
  строки адресуются точно: `border`, `hline`, `cross`, `box`, `rect` рендерятся.

## Что доказано измерениями (обратка SO1)

Не «похоже, что так», а измерено с двух концов регистра командами `so` / `sord`:

- **длина цепи ровно 240 бит** — бегущая единица выходит на такте 240; каскада
  SOUT1→SIN2 нет (SIN1 и SIN2 на плате объединены);
- **биты ложатся точно по таблице даташита** — блоки, отправленные в позиции
  0 / 32 / 64, выходят на тактах 0 / 32 / 64; одиночный бит в индексе 192
  (= бит 193 = начало поля сеток G1) читается на такте 191; бит в конце потока —
  на такте 231.

Вывод: framing, длина цепи и раскладка бит **верны**, дефект ниже — не в протоколе.

## Сверка с таблицей INTERFACE TIMING (замер логическим анализатором)

Hantek 6022BL в режиме `fx2lafw`, 24 МГц, каналы `SIN→D0 CLK→D1 LAT→D2 BLK→D3`.
Скрипт `tools/vs_ds.py`. Все нормируемые параметры — в допуске:

| Параметр | Даташит | Измерено |
|---|---|---|
| CLK Cycle | ≥ 400 нс | 7875 нс |
| CLK High | ≥ 200 нс | 1208 нс |
| CLK Low | ≥ 200 нс | 6667 нс |
| SIN Setup | ≥ 40 нс | 2958 нс |
| SIN Hold | ≥ 50 нс | 667 нс |
| LAT High | ≥ 300 нс | 3417 нс |
| CLK then LAT | ≥ 250 нс | 21792 нс |
| BLK Hold | ≥ 10 мкс | 1939 мкс |
| Бит в посылке | 240 | 240 |

Расходятся с даташитом только два пункта, оба — следствие электрики соединения:

1. **Наводка CLK → SIN:** 15 % переходов линии данных (120 из 812) приходятся на
   ±100 нс от фронта такта, тогда как собственные переходы данных идут за ~3 мкс
   до него. Такого параметра в таблице нет; именно эти выбросы записываются в
   регистр лишними единицами. На осциллограмме видно: после импульса данных идут
   «отскоки», синхронные с импульсами CLK.
2. **Кадр 91 мс (11 Гц) вместо < 10 мс (> 100 Гц)** — плата за пункт 1: такт
   приходится держать на ~127 кГц вместо разрешённых 2,5 МГц.

Смаз измеряется без камеры, командой `sord` (`tools/integrity.py`): одиночная
единица, записанная в позицию N, читается обратно как прогон из K разрядов.
K = 1 — идеал. Замеры: K падает с 25 до 4…7 при увеличении времени установки
(`cfg setus`), до 1 — только при ~65 мкс/бит, что для кадра неприменимо.
Показательно, что K упал с 25 до 7 сам собой, когда подключили землю анализатора.

**Лечение (железо, по убыванию эффекта):** подтяжка SIN к GND 1–4,7 кΩ у разъёма
модуля; короткая отдельная толстая земля Nucleo GND → GND модуля; развести CLK и
SIN, между ними земляной провод; 100–330 Ω последовательно в CLK. Проверка после
каждого шага — `sord`, полминуты.

## Открытый дефект (аналоговая часть модуля)

Один сеточный бит зажигает не одну сетку, а **скользящее окно ~57 столбцов
(~19 сеток)**. Позиция окна едет ровно с шагом сетки (3,5 столбца на бит), т.е.
адресация верная. Ширина не зависит от числа сеточных бит, сохраняется при
остановке тактов на 300 мс, не лечится длиной импульса BLK, сужается при
замедлении такта. При этом когда включено много сеток сразу — точки чёткие и
раздельные. Практический эффект: плотное и горизонтальное содержимое рендерится
корректно, разряжённые вертикальные детали расплываются.

Куда смотреть: цепь смещения `Ek` и резистор **22 Ω во входе VDD2** из
`INTERFACE EXAMPLE` даташита; поведение VDD2 под малой нагрузкой (1 сетка против 44).

## Гочи, стоившие времени

1. **Аппаратный SPI на 2 МГц не работает** — при любых данных заливает экран
   (пустой кадр светится). Рабочий вариант — битбенг ~1,4 МГц (`bb 1`).
2. **OpenCV + MSMF врёт про экспозицию**: `get` всегда −6, кадр отражает
   предыдущую установку. Использовать `cv2.CAP_DSHOW` (см. `tools/camchk.py`).
3. **Выдержка камеры должна быть длиннее кадра дисплея.** Кадр ~10–26 мс; при
   выдержке 4 мс снимаются 2 слота из 44 — отсюда ложные «лестничные края» у
   `fill` и ложное «вертикальная линия не рендерится».
4. Мерить в родном разрешении матрицы (кроп → 128×32). При биннировании в 32
   столбца шесть соседних фаз `afbecd` физически не разделяются.
5. `src/main.c` **не править через PowerShell `Set-Content`** — перекодирует
   русские комментарии в мойибаке.

## Прошивка: команды консоли

```
Графика:  clr fill border box [W H] rect X Y W H chk N hline Y vline X cross
          px X Y V | one X Y | str X TXT | text | iv (инверсия)
Конфиг:   cfg [k v], k = slots gstep dbl triad par mir miry rev bytes dup mode
          on blk hold blkpol latpol nolat gcp bbdly slotus
Режимы:   mode 0 гашение на весь сдвиг | 1 латч внутри гашения
          mode 2 гашение защёлкой нулей | 3 точная последовательность даташита
Драйв:    bb 0|1 (битбенг) | perm dclb (роли пинов) | pins 0|1 | ef 0|1 | hv 0|1|z
Отладка:  gfix N | gall | probe N | noprobe | scan 0|1 | st | help
Сырой поток: raw s n t | rz t | rb s n | rc s n | flush
Обратка:  so [nclk] (длина цепи) | sord [nbits] (паттерн туда-обратно)
```

Рабочий набор для картинки:
`bb 1` → `noraw` → `gall` → `cfg mode 0` → `cfg on 120` → `cfg slotus 220` → `box`

## Сборка и прошивка

```powershell
& "$env:APPDATA\Python\Python312\Scripts\pio.exe" run -d fw-nucleo-bringup
& "C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe" `
    -c port=SWD mode=UR reset=HWrst -d "fw-nucleo-bringup\.pio\build\nucleo_f411re\firmware.elf" -v -rst
```

ST-Link на плате со старой прошивкой (V2J37M26) — заливать именно
`STM32_Programmer_CLI` в режиме `mode=UR` (under reset), не через OpenOCD.

## Тулы на хосте (`tools/`)

Проверка результата — веб-камерой, направленной на дисплей (внешняя, не встроенная).

| Файл | Назначение |
|---|---|
| `vfd.py` | `send` — команды в прошивку; `shot` — снимок; `seq` — серия команд с монтажом |
| `dot.py` | замер в родном разрешении 128×32: где именно горит точка |
| `sweep2.py` | развёртка по шаблону команды + профили строк/столбцов |
| `map.py` | карта сдвигового регистра по камере |
| `combo.py` | перебор упаковок бит (triad × par × mir × dbl × gstep) |
| `camchk.py` | проверка, применяется ли экспозиция (MSMF против DSHOW) |

`box.json` — область дисплея в кадре, машинно-зависимая; пример в
`box.json.example`, получить свою: `python vfd.py shot "fill" --find`.
