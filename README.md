# VFD-дисплей MN12832L как устройство Wiren Board

Вакуумно-люминесцентный дисплей Noritake Itron MN12832L (128×32) с
микроконтроллером в роли фронтенда: на шине он выглядит обычным модулем Wiren
Board — отвечает по Modbus, виден в MQTT, обновляется штатным
`wb-mcu-fw-flasher`.

Пиксели по шине не гоняются. Контроллер передаёт **содержимое** — строки, числа,
примитивы, время, — а рендер (шрифты, лого, куб, часы) живёт в микроконтроллере.

Как это выглядит в работе: [`docs/board/screen-panel.jpg`](docs/board/screen-panel.jpg)
и [`docs/board/video-panel.mp4`](docs/board/video-panel.mp4).

## Как пользоваться из дашборда

Устройство появляется в MQTT как `vfd`, когда порт с ним добавлен в
`wb-mqtt-serial`. Шаблон — `fw-vfd/wb/config-vfd-mn12832l.json`, класть в
`/etc/wb-mqtt-serial.conf.d/templates/`.

| Контрол | Что делает |
|---|---|
| `Режим` | 0 пусто, 1 текст, 2 часы, 3 лого, 4 куб, 5 демо |
| `Строка 1..7` | текст строки: 24 знака латиницей, 12 кириллицей |
| `Стр N: X Y Font` | где и каким шрифтом рисовать строку N |
| `Линия X Y X Y w` | линия от точки до точки, `w` — толщина |
| `Круг X Y d fill` | окружность по центру и диаметру, ненулевое `fill` заливает |
| `Рамка X Y X Y fill` | прямоугольник по двум углам |
| `Точка X Y` | точка, третье число `0` гасит её |

### Правила, которые стоит знать

**Разделитель любой:** `0 22 1`, `0,22,1`, `60-0-0` — одно и то же. Не годится
только точка с запятой: её съедает сам `wb-mqtt-serial` по дороге к устройству.

**Ноль по оси Y внизу.** `2 10 6` значит: от левого края 2 точки, от низа 10,
шрифт 6.

**Пустое поле — это пробел.** Полностью пустое значение MQTT удаляет вместе с
топиком, и контрол пропадает из интерфейса, поэтому модуль отдаёт пробел, а
пробел считает пустотой. Чтобы убрать строку или примитив — поставь пробел.

**Примитивы копятся:** каждая новая запись в линию, круг или прямоугольник
дорисовывается поверх кадра, прежние остаются — так из одного поля собирается
целая картинка. Стереть всё — режим 0.

**Строки перерисовываются поштучно:** меняется текст — гасится место только этой
строки, графика и соседние строки не страдают. Отсюда обычный порядок работы:
сначала выложить графику, потом задать координаты и шрифты, дальше менять только
тексты.

**Шрифты:** 0..2 текстовые с кириллицей (5×8, 6×10, 7×13), 3..10 крупные наборы
«цифры и знаки» (`:.,-+/` и градус) высотой от 19 до 32 точек.

**Часы** идут от времени, которое пишет контроллер: батарейного хода у модуля нет.

### Демка

`fw-vfd/wb/demo-graph.sh` — щиток с двумя графиками: слева значения в рамках,
справа оси со шкалой, по которым чертятся точки. Кнопка для дашборда —
`fw-vfd/wb/vfd-demo.js`, класть в `/etc/wb-rules/`.

## Работа с регистрами напрямую

Modbus RTU, адрес 1, 115200 8N1. Полная карта — `fw-vfd/include/regmap-structs.h`,
она же источник адресов для самой прошивки.

| Адрес | Что |
|---|---|
| `0x10` | режим |
| `0x11` | шрифт 0..10 |
| `0x12` | набор цифр для часов |
| `0x14` | окно показа в слоте, мкс (яркость) |
| `0x15` | флаги, бит 0 — инверсия |
| `0x16` | запись 1 стирает всё содержимое |
| `0x20`–`0x22` | unix-время (старшее слово первым) и смещение зоны, минуты |
| `0x30`–`0x34` | чтение: время кадра, период слота, наработка, битые кадры |
| `0x200 + N*0x20` | строка N: 24 байта текста, следом 12 байт параметров |
| `0x300` `0x310` `0x320` `0x330` | линия, окружность, прямоугольник, точка |

Стандартные адреса Wiren Board поддержаны, поэтому модуль узнаётся штатными
инструментами: `129`/`131` — уход в загрузчик, `250` — версия прошивки, `290` —
подпись `vfd128x32`, `330` — версия загрузчика.

```python
import serial, struct
def crc(d):
    c = 0xFFFF
    for b in d:
        c ^= b
        for _ in range(8): c = (c >> 1) ^ 0xA001 if c & 1 else c >> 1
    return c
p = serial.Serial("/dev/ttyACM0", 115200, timeout=1)
def wr(reg, payload):                                    # функция 0x10
    body = bytes([1, 0x10]) + struct.pack(">HHB", reg, len(payload) // 2, len(payload)) + payload
    p.write(body + struct.pack("<H", crc(body)))

wr(0x10,  b"\x00\x01")                                   # режим: текст
wr(0x200, "Привет".encode().ljust(24, b"\0"))            # строка 1
wr(0x20C, b"2 10 1".ljust(12, b"\0"))                    # её место и шрифт
wr(0x300, b"0 0 127 31 2".ljust(16, b"\0"))              # линия толщиной 2
```

Обновление прошивки — штатным инструментом контроллера:

```
wb-mcu-fw-flasher -j -b 115200 -s 1 -d /dev/ttyACM0 -a 1 -f app.wbfw
```

# Разработка

## Устройство прошивки

Раскладка как в `wirenboard/wb-embedded-controller`: CMSIS и прямые регистры без
вендорского HAL, кооперативный цикл без ОСРВ, модули с парой «инициализация и
периодическая работа».

```
fw-vfd/system/     стартовый код, таблица векторов, заглушки newlib
fw-vfd/src/        rcc, gpio, spi, uart и вся логика (vfd-app.c)
fw-vfd/src/boot/   загрузчик
fw-vfd/ldscripts/  раздельные скрипты для загрузчика и приложения
fw-vfd/include/    регкарта, протокол обновления, шрифты и наборы цифр
fw-vfd/tools/      mkwbfw, хостовой флешер, помощник для опроса с контроллера
fw-vfd/wb/         шаблон устройства, демка, правило с кнопкой
fw-vfd/docs/       устройство загрузки шрифтов
```

Сборка: `python fw-vfd/build.py` (на стенде нет `make`) либо `make` — флаги те же.
Приложение ~43 КБ флеша и ~4,6 КБ ОЗУ.

## Загрузчик

Протокол обновления Wiren Board, снятый с исходников `wb-mcu-fw-flasher`: вход по
записи 1 в регистр 129, инфоблок 32 байта функцией `0x10` по адресу `0x1000`,
данные кусками 136 байт по `0x2000`, в конце сверка CRC32 и прыжок в приложение.
Загрузчик занимает первые 16 КБ флеша (сам он 1,5 КБ), приложение линкуется с
`0x08004000`. Проверено: штатный флешер прошивает модуль целиком.

## Железо стенда

NUCLEO-F411RE, дисплей питается от лабораторного блока, общая только земля.

```
CLK = PA5 (SPI1_SCK)   SIN = PA7 (SPI1_MOSI)   консоль и шина = PA2/PA3 (USART2)
LAT = PB6              BLK = PB4               EF = PB8 (накал, активен HIGH)
HV  = PB9 — вход, не драйвим
```

**Обязательная доработка: подтяжка линии SIN к земле, 1 кОм.** Без неё каждый
записанный бит расползался на 17 разрядов регистра, и произвольная графика была
невозможна. На плате модуля в каждой линии стоит 330 Ω последовательно (R1, R2,
R26, R25, R4, R5), а со стороны стекла линию данных подтягивает вверх —
получался делитель, и ноль на дальнем конце не опускался ниже даташитного
`VIL = 0,7 В`. Резистор на землю переломил делитель: смаз стал ровно 1 разряд на
всех скоростях, включая 12,5 МГц. **Для мезонина развести этот резистор на плате.**

Рабочая точка: SPI 12,5 МГц, режим 0 (гасим → сдвиг 240 бит → LATCH → показ),
окно показа 180 мкс, слот 227 мкс, кадр 10 мс = 100 Гц (даташит требует < 10 мс).

## Гочи, стоившие времени

1. **FPU включается руками.** Собрано с `-mfloat-abi=hard`, а `CPACR` не настроен
   — первая же инструкция с плавающей точкой даёт HardFault с битом `NOCP`.
   У HAL это делал `SystemInit`.
2. **Линкер выравнивает первый LOAD-сегмент вниз на страницу 64 КБ**: сегмент
   начинается с `0x08000000` и тянет за собой ELF-заголовок, а программатор пишет
   его поверх загрузчика — при этом рапортуя об успешной верификации. Лечит
   `-Wl,--nmagic`.
3. **Конец кадра Modbus нельзя ловить по паузе**, когда главный цикл занят
   выводом кадра ~10 мс: байты одного запроса попадают в разные проходы. Длина
   кадра RTU однозначно задана функцией — её и ждём.
4. **`wb-mqtt-serial` хранит значения контролов** в `/var/lib/wb-mqtt-serial/` и
   восстанавливает их при старте, поэтому «очищенные» поля возвращаются.
5. **Пустая удержанная посылка удаляет топик MQTT**, и контрол исчезает из
   интерфейса — отсюда пробел как признак пустого поля.
6. **Скрипты для контроллера только с LF:** с CRLF `sh` спотыкается о `\r`.
   Закреплено в `.gitattributes`.
7. **Файлы с русским текстом не править через PowerShell `Set-Content`** — он
   перекодирует их в мойибаке.

## Что дальше

Окно произвольной картинки 256×64 — регистры описаны, кода нет. Загрузка шрифтов
без пересборки прошивки — см. `fw-vfd/docs/fonts-upload.md`. Порт на GD32E235
(128 КБ флеша, 16 КБ ОЗУ): у Cortex-M23 нет счётчика тактов DWT, поэтому
микросекундные задержки лягут на аппаратный таймер.

Каталог `fw-nucleo-bringup/` — прежняя версия на HAL, оставлена для сравнения.
